# g_spiral_expr_sketch

**Purpose:** The spiral as ONE `list<point>` expression → a **SKETCH** → `r_weld_extrude`
— the sketch edition of `g_spiral_expr` (which uses a polygon). The headline: the
sketch's **2D stage renders the profile generated by the expression** (the spiral
band, live, updating on param edits), so you can *see* what the expression builds.

**Location:** `basic/spirals/g_spiral_expr_sketch.asm.ts` (volume). The fifth spiral:
`g_spiral` (poly_repeat) · `g_spiral_sketch` (sketch_repeat) · `g_spiral_repeat`
(part Repeat) · `g_spiral_expr` (expr → polygon) · **`g_spiral_expr_sketch`** (expr → sketch).

## Composition (3 nodes)
1. **Expression** (`profile_pts`, `shape:'list', elem:'point'`) — the same readable
   multi-line spiral formula as `g_spiral_expr` (`outer(i)` / `inner(j)` helpers +
   `return concat(map(...), map(...))`).
2. **Sketch** — a single `expr-list-ref` op splicing the expression's `list<point>`
   output as the sketch's profile. The 2D stage evaluates the expression
   (`sketch-state.evalExprListPoints` → `compileListFormula` → eval with the param
   scope) and draws the spiral; the bake emit splices the compiled list as line ops
   (parametric). The "+ expr" sketch-card button (`addSketchExprList`) creates this.
3. **`r_weld_extrude`** — extrudes the sketch profile `length` in z.

## Parameters
`NPts` 360 · `r0` 0.4 · `growth` 1 · `turns` 2 · `width` 0.2 · `length` 2.

## Why it matters
First node OTHER than the polygon to consume a `list<point>` expression — the sketch
as a live expr-builder consumer (typed-ports). The 2D-stage visualization (the
expression's profile drawn in the sketch) is the new capability vs `g_spiral_expr`.
Feature shipped via `SketchExprListRef` + `expandSketchOps(evalExprList)` + the bake
splice. Bakes ~8004 verts.
